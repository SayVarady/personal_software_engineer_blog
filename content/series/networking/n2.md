The OSI Model is a conceptual framework that translate the communication into a series of layers. There are 7 layers in the OSI Model, each with a specific purpose. It handles the networking of your computer and it comes with your OS kernel.
The layers are: 
- L7 - Application
- L6 - Presentation
- L5 - Session
- L4 - Transport
- L3 - Network
- L2 - Data Link
- L1 - Physical

**Disclaimer** I am not a network engineer not someone who is an expert in networking. I am just a random software engineer who happens to be interested in knowing how data moves from one place to another. Or in other words, how data moves from one computer to another computer. 

Let's get into it.

Previously, I have already explained that every computers on the internet are connected to a network. Those computer had its own unique Identity number that represents itself on the network - `IP address`. So the communication on the internet usually involves 2 or more computers. The most common one is a `client-server` model where one computer acts as the server and the other acts as the client. To simply put, the client computer usually sends a request to the server computer (can receive request on the internet) asking for a content. The server computer then responds with the requested content. However, it is more complicated than we thought. It involves resolution, translation, routing, validation and many other things before your content is delivered. But I will just focus on the OSI Model in this writing. So what we are discussing today is only the process of the data being translate into bits before it is being transfered over the network. It does not involve the communication with other computer yet. 

## L7 - Application Layer

Let's say you type in `www.google.com` which mean you are trying to access to the Google website. It usually return a Google webpage. So the application layer is responsible for preparing your request into a format that another layer understand. It attaches your request with your credentials (if any) and other metadata before sending it to the next layer. You often see something like Header, Body being attached to your request. Such as Content-type, Authorization, Accept.etc. This layer use HTTP/HTTPS protocols to communicate with the server.

## L6 - Presentation Layer

It is responsible for translating your data into a format that the different system can understand. It also handle the compression and encryption of your data. This an optional layer. If you use HTTPS, you will have a Presentation Layer that handle the encryption of your data.

## L5 - Session Layer

This layer is responsible for establishing, maintaining, and terminating sessions between two or more devices. It handles the synchronization and flow control of data between the devices. It attaches the session ID to the data before sending it to the next layer.

## L4 - Transport Layer

This layer is responsible for sequencing your data. So after the previous layer all your data had been encrypted, so its job is now to break it into smaller chunks (called `segments`) and send it to the next layer. Here is the interesting part, it also ensure that the segments are received in the correct order and without any loss. It uses the source and destination port numbers to identify the application that is sending or receiving the data.

## L3 - Network Layer

This layer is responsible for routing your data to the correct destination. It uses the IP address to identify the destination device. The source and IP address are attached to the sequence of `segments` from previous layer after that those data are called packets. The data on this layer is called `packets`.

## L2 - Data Link Layer

It breaks the data from previous packets into smaller chunks (called `frames`) and sends it to the next layer. It attached the MAC address to the `frames` before sending it to the next layer. Sometimes, MAC addresses is not available, so the computer use `ARP - Address Resolution Protocol` to resolve the MAC address of the device using the IP address.

## L1 - Physical Layer

All your data is converted into bits 1 and 0 and sent over the wire, air, or fiber optic cable. Every device that connects to the same network will receive those bits at the moment. Since this layer has no idea where to send those bits. So the devices that connects to the network operate an Address Resolution Protocol (ARP) to resolve the MAC address of the device using the IP address (By Layer 2) of the received device and it rejects the packet if the MAC address does not belong to itself.
